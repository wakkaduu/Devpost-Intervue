Same stack as your first build, fresh Supabase project, server-only AI keys. Core first, extras added one verified step at a time.

The architecture

Follow one answer through the system

The AI review, in the background

Your one open question. POST /api/review → validate and rate-limit → build the prompt (question, answer, earlier feedback, rules like "quote what they said") → Gemini (12 s limit) → Groq → built-in basic grader → structured feedback back to the browser. Check during the build: the response's source is ai or basic, and server logs name the provider.

Run it

npm install, fill .env.local, run supabase/schema.sql in your new project, npm run dev, open localhost:3000 in Chrome and record the demo. Vercel is optional and does not replace the video or the public repo.

Failure modes and simplifications

If it breaksAI down → basic feedback notice + retry. Mic denied → typed fallback. Save fails → results stay on screen; saves are idempotent.
SimplifiedBrowser voice instead of a paid speech service (none was ever used). No demo-account seed in a public repo. No user-facing API-key modal.
To verify early in the buildGemini and Groq model names and limits; next-auth v5 beta with the chosen Next version.
